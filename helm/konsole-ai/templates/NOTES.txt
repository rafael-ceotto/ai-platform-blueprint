Konsole.ai ({{ .Chart.Name }} {{ .Chart.Version }}) has been installed as
release "{{ .Release.Name }}" in namespace "{{ .Release.Namespace }}".

This chart has only ever been validated via `helm lint`, `helm template`,
and a local `kind` smoke test (`make kind-smoke-test`) -- it has never been
installed against a real cloud cluster. See docs/adr/0017.

1. First run only: pull the two models Ollama needs (there's no automated
   pull step for a real cluster, unlike the docker-compose.yml quickstart):

     kubectl exec -it {{ include "konsole-ai.fullname" . }}-ollama-0 -- ollama pull {{ .Values.api.env.OLLAMA_MODEL }}
     kubectl exec -it {{ include "konsole-ai.fullname" . }}-ollama-0 -- ollama pull {{ .Values.api.env.EMBEDDING_MODEL }}

2. Reach the API and UI locally:

     kubectl port-forward svc/{{ include "konsole-ai.fullname" . }}-api {{ .Values.api.service.port }}:{{ .Values.api.service.port }}
     kubectl port-forward svc/{{ include "konsole-ai.fullname" . }}-ui {{ .Values.ui.service.port }}:{{ .Values.ui.service.port }}

   Then open http://localhost:{{ .Values.ui.service.port }} (UI) or
   http://localhost:{{ .Values.api.service.port }}/docs (Swagger).
